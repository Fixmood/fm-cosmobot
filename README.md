# FM

FM 是基于 Cosmobot 定制的多平台智能机器人，面向 QQ 与 Matrix 提供对话、上下文记忆、中文跟打训练、赛事数据、媒体处理及运行管理能力。

本仓库包含 Haskell 运行时、FM 专用处理器与 Agent 工具、测试和运维脚本。生产环境的凭据、用户数据、消息记录、媒体缓存及数据库不在仓库中维护。

## 核心能力

### 对话与 Agent

- 支持 QQ 群、QQ 私聊和 Matrix 房间。
- 按平台、会话和用户隔离上下文、记忆、权限与个性化设置。
- 支持 OpenAI 兼容的聊天、图像和音频模型。
- 支持模型管理、工具审计、结果压缩、任务续行和沙盒执行。
- 支持网页检索、文件处理、图片操作、语音生成、定时任务和仓库操作。

### 跟打训练

- 按关键词、长度、题材和计算难度抽取练习文章；文库会为整篇正文保存题材、文体、难度和分类置信度，发文头部会显示 `难度分数·题材·文体`。
- 支持持续发文、续段、恢复上一篇、停止和撤回。
- 支持顺序或乱序单字练习、条件阈值、段数与进度管理。
- 解析并存储跟打成绩，按提交用户和会话校验续发资格。
- 对文库执行正文清洗、去重、索引、整篇题材/文体分类和难度计算，并支持分类元数据批量回填。

### 赛事与报表

- 获取并保存当前及历史赛文。
- 定时同步每日赛文并补齐缺失日期。
- 历史赛文使用独立会话，提交对应成绩后自动续发。
- 收录普通跟打、公开赛事和每日 555 赛文成绩。
- 提供排行榜、历史查询、统计汇总和成绩曲线图。

### 消息与管理

- 在 QQ 与 Matrix 之间桥接消息并适配各平台格式。
- 支持长消息分段、QQ 合并转发、媒体发送和消息撤回。
- 支持受控的对话接管与跨会话转发。
- 支持群能力、房间访问、触发规则、循环保护和服务状态管理。

## 工具系统

FM 当前默认注册 83 个聊天 Agent 工具，覆盖模型与配额、消息、文库、赛事、桥接、媒体、记忆、执行环境和后台任务。另有 3 个工具仅在 ACP 客户端会话中注册。

每个工具的名称、用途和所属能力详见 [`docs/FM_TOOLS.md`](docs/FM_TOOLS.md)。工具的实际可用性由运行配置、平台、会话类型、消息意图、群能力和管理员权限共同决定。

## 系统架构

```text
QQ / Matrix
    |
    v
平台驱动 -> 标准消息 -> 路由与处理器 -> Agent 运行时
                                      |       |       |
                                      v       v       v
                                     LLM     工具    记忆
                                              |
                                              v
                                        FM 领域服务
                                   文库 / 成绩 / 赛事 / 报表
```

运行时遵循以下依赖方向：

```text
平台事件 -> 核心消息 -> 路由 -> 处理器 -> Effect -> 解释器
```

主要模块边界：

- `Bot.Core.*`：平台无关的消息、路由和会话类型。
- `Bot.Handler.*`：用户可见行为、命令及准入策略。
- `Bot.Agent.*`：Agent 循环、中间件、工具和审计。
- `Bot.Effect.*`：能力接口。
- `Bot.Chat.Driver.*`：平台协议与消息标准化。
- `Bot.LLM.*`、`Bot.Storage.*`、`Bot.System.*`：模型、存储和系统集成。
- FM 领域服务：文库、成绩、赛事归档和报表数据。

## 环境要求

- GHC 9.10.3
- Cabal 3.14.2.0 或兼容版本
- Python 3
- Linux 生产环境
- 启用沙盒时需要 `bubblewrap`
- QQ/OneBot、Matrix 和 OpenAI 兼容模型服务
- 启用跟打与赛事功能时需要 FM 领域服务

Typst、ImageMagick、对象存储、搜索服务及图像或音频模型仅在启用对应功能时需要。

## 构建与测试

```bash
cabal update
cabal build -j all --enable-tests --enable-benchmarks
cabal test -j all --test-options=--hide-successes
```

仅构建生产可执行文件：

```bash
cabal build -j exe:cosmobot
cabal list-bin exe:cosmobot
```

CI 使用相同的 GHC 与 Cabal 版本，并在推送和 Pull Request 时执行完整构建与测试。

## 配置

以 [`cosmobot/config.example.toml`](cosmobot/config.example.toml) 为基础创建运行配置。生产环境按需配置：

- QQ/OneBot 与 Matrix 连接；
- 会话白名单、用户权限和管理员；
- 聊天、图像及音频模型；
- 媒体存储与公开访问地址；
- 记忆、Skill、沙盒和定时任务；
- 搜索及其他第三方服务。

配置文件不得进入版本控制。所有密钥应由部署环境或专用密钥系统管理。

## 部署要求

生产环境应使用不可变运行镜像和持久化数据卷。每次发布必须完成：

1. 构建并测试目标版本。
2. 生成包含已验证可执行文件的运行镜像。
3. 确认新容器使用正确的镜像摘要。
4. 检查服务健康、QQ 连接、Matrix 同步和领域服务访问。
5. 对受影响的用户流程执行端到端验证。

编译成功和容器健康不等于消息链路验证通过。

## 安全要求

禁止提交以下内容：

- API Key、Token、密码、Cookie 或代理订阅；
- QQ、Matrix、GitHub 及第三方服务凭据；
- 私钥、生产配置、SQLite 数据库和运行日志；
- 消息历史、用户记忆、成绩数据或媒体缓存。

高权限工具必须进行管理员校验。用户级状态必须以平台和用户身份为键，会话级状态必须以平台和会话身份为键；身份缺失时应拒绝操作。

## 开发规范

- 遵循 [`AGENTS.md`](AGENTS.md) 中的架构和模块边界。
- 功能修改应包含与影响范围匹配的回归测试。
- 提交前运行 `git diff --check`。
- 需要审核的修改通过独立分支和 Pull Request 交付。
- 测试、提交、Issue 和 PR 中不得包含生产数据或凭据。
