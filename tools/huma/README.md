# huma —— `*fix`（虎码解码）的码表工具

这两个脚本是 `*fix` 在**运行时**用的，装在机器人的运行卷上：

```
/opt/fm-cosmobot/runtime/huma/        （容器内 = /data/huma/）
```

仓库里这份是**源码与备份**，不参与 Haskell 构建。

## 文件

| 文件 | 作用 |
|---|---|
| `decode.py` | 解码器。`Bot/Handler/Huma.hs` 的 route 调它。支持候选选择键（`;`=2选、数字、`0`=10选）和**引号字面量**（`"..."` 内原样，外面照解；ASCII 和全角都认） |
| `update_table.py` | 换表：下载/读取 → **校验** → 原子替换。校验不过**一个字都不动** |
| `deploy.sh` | 把这两个脚本装回运行卷（恢复用） |

`huma_index.tsv`（生成的索引）**不在仓库里** —— 它由 `update_table.py` 从主人在 QQ 上传的 txt
现算出来；原始 txt 在 QQ 文件记录里，运行卷上另有带时间戳的 `.bak`。

## 恢复步骤（运行卷丢了 / 换机器）

```bash
bash tools/huma/deploy.sh          # 装脚本
# 然后让主人在 QQ 里重新上传码表 txt，发「更新码表」—— 索引会自己生成
```

## 换表的语义

主人上传 txt 后 **3 分钟内**发 `更新码表` / `上传码表` / `换码表` / `码表更新`（带 `fm` 前缀也认）。

校验项：条目数、编码只能 a-z、锚点字（的一是不了 → u/f/o/c/r）、与旧表首选一致率 ≥90%、
**CRLF 归一**（主人上传的是 CRLF，不处理会让每个编码带上尾随 `\r`，整张表静默失效）。
**任何一条不过就拒绝并说明理由，现有表不动。**

引用的 `ref` 有两种形态：入站文件会被导进媒体库，所以通常是 `media:mf_xxx`
（由 Haskell 侧用 `Media.mediaFileInfoByRef` 解析成本地路径），偶尔才是 https 下载链接。
